# API guide

Interactive docs (`/docs`, `/redoc`, `/openapi.json`) are disabled when
`ENVIRONMENT=production`. Export the schema at build time:

```bash
python scripts/export_openapi.py docs/openapi.json
```

Publish the artifact to an authenticated developer portal. The schema is also
generated by FastAPI at `/openapi.json` in development/staging.

Base URL: `https://api.<domain>/api/v1`

Authentication: `Authorization: Bearer <access_token>`. Obtain a token with
`POST /auth/login` (JSON, not form-encoded). Access tokens live 15 minutes;
refresh tokens are accepted only by `/auth/refresh`.

---

## Authentication

```bash
curl -sS -X POST https://api.example.com/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{
    "tenant_slug": "acme",
    "email": "owner@acme.retail",
    "password": "CorrectHorseBattery9!"
  }'
```

```json
{
  "access_token": "eyJ...",
  "refresh_token": "eyJ...",
  "token_type": "bearer",
  "expires_in": 900
}
```

```bash
curl -sS https://api.example.com/api/v1/auth/me \
  -H "Authorization: Bearer $TOKEN"
```

Errors are deliberately uniform: wrong tenant, wrong email, and wrong password
all return `401 {"detail":"Invalid credentials"}`. Five failures lock the
account for 15 minutes (`423`).

Refresh:

```bash
curl -sS -X POST https://api.example.com/api/v1/auth/refresh \
  -H 'Content-Type: application/json' \
  -d '{"refresh_token":"<refresh>"}'
```

## Render

Requires scope `ai:render`. The request is `multipart/form-data`:

| Field | Type | Rules |
|---|---|---|
| `fabric_image` | file | JPEG/PNG/WEBP, ≤15 MiB, single frame, ≤50 MP |
| `prompt` | string | ≤2000 chars; control characters stripped |

```bash
curl -sS -X POST https://api.example.com/api/v1/ai/render \
  -H "Authorization: Bearer $TOKEN" \
  -F "fabric_image=@fabric.png;type=image/png" \
  -F "prompt=premium cotton weave, studio lighting"
```

`202 Accepted`:

```json
{
  "job_id": "3f0c2f9e-6f7a-4f4e-9a5b-1f9d2f6c8b11",
  "status": "queued",
  "source_preview_url": "https://...presigned...",
  "message": "Queued for malware re-scan and GPU rendering."
}
```

Poll:

```bash
curl -sS https://api.example.com/api/v1/ai/render/<job_id> \
  -H "Authorization: Bearer $TOKEN"
```

| Status | Meaning |
|---|---|
| `202` | queued |
| `401` | missing/expired token |
| `403` | missing `ai:render` |
| `413` | upload >15 MiB |
| `415` | unsupported magic bytes / format |
| `422` | malformed image |
| `429` | GPU leaky bucket exhausted; honour `Retry-After` |
| `503` | ClamAV unavailable and `CLAMAV_FAIL_CLOSED=true` |

A job ID belonging to another tenant returns `404` (uniform IDOR guard).

## Payments

Requires `payments:write`. **There is no amount field.** The API resolves the
price from its SKU catalogue and rejects unknown SKUs.

Every mutating request needs an `Idempotency-Key` header (16–128 chars,
`[A-Za-z0-9_-]`). Replaying the same key with the same body returns the stored
response; reusing it with a different body returns `409`.

```bash
curl -sS -X POST https://api.example.com/api/v1/payments/checkout \
  -H "Authorization: Bearer $TOKEN" \
  -H "Idempotency-Key: 9f2c1b7a4e6d8c0b2a1f3e5d" \
  -H 'Content-Type: application/json' \
  -d '{
    "sku": "render_pack_100",
    "quantity": 1,
    "success_url": "https://app.aifabric.retail/billing/success",
    "cancel_url": "https://app.aifabric.retail/billing/cancel"
  }'
```

- Redirect URLs must be HTTPS and their origin must be in `ALLOWED_ORIGINS`.
- Stripe Checkout handles 3DS2/SCA; card data never touches this API.
- Webhooks verify HMAC/signature, processor CIDR, and amount reconciliation.

Transactions:

```bash
curl -sS "https://api.example.com/api/v1/payments/transactions?limit=50" \
  -H "Authorization: Bearer $TOKEN"
```

## Admin

Requires `admin:all`.

```bash
curl -sS -X POST https://api.example.com/api/v1/admin/tenants \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"slug":"gamma","name":"Gamma Fabrics","plan":"starter"}'
```

This calls `provision_tenant()`: it creates the schema, tables, RLS policies,
triggers, and least-privilege grants in one transaction.

## Error envelope

Unhandled production errors are masked:

```json
{"error":"internal_error","request_id":"..."}
```

Validation errors are sanitised and never echo submitted secrets:

```json
{
  "error": "validation_error",
  "details": [{"loc":["body","password"],"msg":"String should have at least 8 characters","type":"string_too_short"}]
}
```

Include `X-Request-ID` if you have one; it is propagated to logs.
